Sync‑DevTrees Toolchain — README.md
The Sync‑DevTrees toolchain provides a deterministic, reversible, suite‑only synchronization pipeline between:

Repo A (authoritative development repo)  
F:\DEVELOPMENT\Repo_A\forensic_tracer_installer_project_root\forensic_suite_v2\

Repo B (deployable mirror repo)  
F:\DEVELOPMENT\Repo_B\forensic_suite_v2\forensic_suite_v2\

This toolchain ensures Repo B always contains a clean, correct, deployable copy of the suite, ready for host deployment via blue/green slot switching.

The toolchain consists of five scripts:

Sync-DevTrees.ps1 — Proposal mode

Sync-DevTrees.DryRun.ps1 — Print exact commands

Sync-DevTrees.Apply.ps1 — Dry‑run → confirm → backup → apply

Sync-DevTrees.Rollback.ps1 — Restore Repo B from backup

Sync-DevTrees.Validate.ps1 — Confirm Repo B matches Repo A

All scripts operate on the suite subtree only, with a consistent set of exclusions.

1. What gets mirrored
The mirror includes everything required for runtime, operator tooling, dashboards, services, and orchestrator integration:

Python source (*.py)

PowerShell scripts (*.ps1)

Configs (*.json, *.yaml, .env)

Dashboards (*.html, *.json, *.ps1)

SQL files

Plugins (btc, eth, tron, custom)

GUI files (PySide6)

Documentation (*.md)

Developer helper scripts (build.ps1, Fix-Imports.ps1, etc.)

This produces a complete, correct suite tree for deployment.

2. What is excluded
The following are never mirrored:

__pycache__/

*.pyc, *.pyo

*.egg-info

legacy/

dist/

Output/

installer_payload/

logs/

tests/

*.whl, *.tar.gz

These exclusions remove noise, dev artifacts, build artifacts, and unused legacy code.

3. Mapping CSV
All scripts rely on:

F:\tools\repo_mapping_suite.csv

This CSV is generated by forensic_suite_repo_mapping.ps1 and contains:

Relative path

Presence in Repo A

Presence in Repo B

SHA256 hashes

Full paths

The mapping is already filtered to enforce all exclusions.

4. Script Overview
Sync‑DevTrees.ps1 — Proposal Mode (safe)
Shows what would change in Repo B without modifying anything.

Reports three categories:

Extra in Repo B (would be deleted)

Missing in Repo B (would be copied)

Drift (hash mismatch, would be overwritten)

This script is always safe.

Sync‑DevTrees.DryRun.ps1 — Print exact commands
Prints the exact PowerShell commands that Apply mode will execute:

Remove-Item for deletions

Copy-Item for missing files

Copy-Item -Force for drift overwrites

New-Item -ItemType Directory for folder creation

No changes are made.

Sync‑DevTrees.Apply.ps1 — Dry‑run → confirm → backup → apply
This is the authoritative sync engine.

Workflow:

Runs DryRun internally

Prints exact commands

Prompts for confirmation

Creates a timestamped backup under:

F:\tools\RepoB_Backups\RepoB_YYYYMMDD_HHMMSS\

Deletes extra files

Copies missing files

Overwrites drifted files

Only the suite subtree is modified.

Sync‑DevTrees.Rollback.ps1 — Restore Repo B from backup
Restores Repo B’s suite subtree from any timestamped backup created by Apply mode.

Lists available backups

Requires explicit selection

Requires confirmation

Overwrites only the suite subtree

Top‑level deployment scripts remain untouched.

Sync‑DevTrees.Validate.ps1 — Confirm Repo B matches Repo A
Performs a byte‑for‑byte comparison using SHA256 hashes.

Reports:

Missing in Repo B

Extra in Repo B

Drift (hash mismatch)

If all three are empty, Repo B is a perfect mirror of Repo A.

5. Operational Workflow
Daily development

Sync-Dev

Before building installer or deploying to hosts

Sync-DevTrees.Apply.ps1
Sync-DevTrees.Validate.ps1

If something goes wrong

Sync-DevTrees.Rollback.ps1

6. Safety Guarantees
Proposal mode is always safe

DryRun prints commands only

Apply mode requires confirmation

Apply mode creates a timestamped backup

Rollback restores from backup

Validate confirms integrity

Only the suite subtree is ever modified

Top‑level Repo B deployment scripts are never touched

This ensures deterministic, reversible, production‑grade synchronization.
